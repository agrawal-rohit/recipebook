## Default behavior

`npx pebbles` uses the default registry bundled into the CLI package.

```bash
npx pebbles list
```

## Adding registry items

Install items from the bundled or custom registry into the current project:

```bash
npx pebbles add pr-template-configuration
npx pebbles add testing-configuration --overwrite
npx pebbles add
```

`add` captures shared and item-local conditions (local `infer` handlers can suggest prompt defaults), selects every matching pack plus any base files, fetches compiled items from the index location, runs any local item hooks, writes files into the project, and optionally installs Node packages using the selected Node package manager.

That keeps the default experience fast and offline-capable after install.

## Socket Firewall (sfw)

Socket Firewall Free ([docs](https://docs.socket.dev/docs/socket-firewall-free)) blocks known malicious packages at install time. It is an **ecosystem tool, not a pebbles feature** — the CLI itself only ever runs plain package-manager commands.

To install `sfw` globally, run:

```bash
npm install --global sfw
```

### Secure-by-default installs

`sfw` works purely as a command prefix (`sfw pnpm install`), and the supported package managers cannot be intercepted from a project file. The officially documented way to make regular commands safe by default is a one-time shell alias ([sfw-free README](https://github.com/SocketDev/sfw-free#optional-use-shell-aliases-to-avoid-typing-sfw-every-time)):

```bash
# ~/.zshrc (or ~/.bashrc)
alias npm="sfw npm"
alias pnpm="sfw pnpm"
alias yarn="sfw yarn"
```

After `source ~/.zshrc`, every bare `pnpm install`, `npm ci`, or `yarn add` in any project runs under the firewall. On the JavaScript side `sfw` supports npm, pnpm, and yarn — Bun and Nub installs are not covered.

### CI coverage

The bundled `setup-workspace` action sets up `sfw` via `SocketDev/action` and runs the hardened install as `sfw {{pmInstallCi}}`.

## Using a custom registry

Pass `--registry` to point `pebbles` at another registry document:

```bash
npx pebbles --registry https://example.com/registry.json list
```

You can also set an environment variable:

```bash
export PEBBLES_REGISTRY="https://example.com/registry.json"
npx pebbles list
```

Resolution order is:

1. `--registry <url-or-path>`
2. `PEBBLES_REGISTRY`
3. `./registry.json` in the current working directory
4. the registry document bundled into the CLI package (after install / `prepack`)
5. workspace fallback `packages/registry/registry.json` during local development
