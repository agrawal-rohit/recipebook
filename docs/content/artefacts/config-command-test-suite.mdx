## Thought

### What we're testing

We want a test suite proving the **safe and reliable behaviour of the `config` command** (renamed to **`configure`** by the inbuilt-registry removal refactor — clean break, no alias). All target logic lives in `packages/cli`. Tests should exercise the **public command exports** (not internals) so they survive refactors, and unit-test the config read/write/validation primitives against a temp filesystem via the injected `env` argument.

All primitives accept an optional `env` argument for path resolution — **this is the seam for filesystem isolation** in tests.

### CLI wiring (integration surface)

- Entry: `src/index.ts:1` `run()` builds a `cac` instance, registers `configure <action> [source]` via `registerCommandsCli`. `bin/cli.mjs` runs `dist/index.js`.
- Command dispatch: `commands/index.ts` `configureCmd.action` → `runConfigureAction(action, source)` → `configGetCommand` / `configSetCommand` / `configUnsetCommand`.
- Actions: `ConfigureAction` enum `GET/SET/UNSET` (renamed from `ConfigAction`); `parseConfigureAction` (renamed from `parseConfigAction`) rejects anything else with `Usage: cheetos configure <get|set|unset> [source]`.
- `get`/`unset` reject a source (`assertNoConfigSource`); `set` accepts an optional `[source]` and otherwise prompts via `textInput`.
- Command-body exports keep their `config*Command` names — they describe the config-file domain, not the command name.
- Errors bubble to `runCliCommand` (`cli/errors.ts`) which prints and `process.exit(1)`.

## Behavioural contract (to encode in tests)

### Config file location & format — `cli/config.ts`

- `configPath(env)`: honours `XDG_CONFIG_HOME` (trimmed) else `~/.config`; final path `<base>/cheetos/config.json` (line 58–67).
- Format: JSON object with **only** key `registry` (optional string). Written with tab indent + trailing newline, UTF-8 (line 198–203).
- `writeConfig`: `validatedConfig` (line 75) trims and rejects non-string/empty `registry`; `mkdir -p` parent with mode `0o700`; writes file with mode `0o600`; refuses to write over a symlink/dir/special node (`assertConfigPathIsRegularFile`, line 84, called with `"write"`).

### Reading / defaults / merging

- `readConfig` returns `{}` when file is absent (line 161) or vanishes between lstat and read (`isMissingPathError`, line 170–172).
- Unset state: `configGetCommand`/`configUnsetCommand` print `registry:    (not set)` plus a dim hint (`Run \`cheetos configure set <source>\` to add one.`) — the old `defaultRegistryUrl()` / `publishedRegistryUrl` fallback is removed with the inbuilt registry.
- No "merging" of multiple sources in config itself; merging across CLI flag / env / saved config happens in `utils/registry.ts:locateRegistry` — **explicit sources only**: `--registry` flag > `env.CHEETOS_REGISTRY` > saved config, and none resolving throws `NoRegistrySourceError` (no cwd/fallback/bundled discovery).

### Validation / error paths to assert

`Callout type="warn"`

- **Config document** (`cheetosConfigFromJson`, `cli/config.ts:74`): non-object root → `"Config root must be a JSON object."`; unknown key → `"Unknown config key "<key>"."`; `registry` present but not non-empty string → `'"registry" must be a non-empty string URL or file path.'`; size > `CONFIG_FILE_BYTE_LIMIT` (65 536, line 44) → `"…file is too large."`; JSON parse failure → wrapped `"Malformed cheetos config at <path>: …"` (line 176); symlink/dir/special node → reject on both read and write (lines 84–104).
- **Registry source** (`toPersistedRegistrySource`, `commands/config.ts:122`): empty → `"Registry source must not be empty."`; non-HTTPS scheme `scheme://` → `"Registry source must be an HTTPS URL or a local file path."`; HTTPS URL must pass `assertSafeRemoteUrl` (HTTPS only, no credentials, no localhost/`.localhost`, no IP literals — `core/src/urls.ts:110`); local path must resolve to an existing **regular** file (no symlink, no dir — `assertLocalRegistryStatIsFile`, `commands/config.ts:88`; missing → ENOENT message).

### Safety-critical surface

`Callout type="warning"`

- **Writes user-global filesystem**: `writeConfig`/`unsetRegistryConfig` mutate `~/…/cheetos/config.json` (or `XDG_CONFIG_HOME`). All writes use mode `0o600`; parent dir `0o700`.
- **Writes only touch the config path** — the registry source itself is validated but the `config` command never reads/writes registry contents.
- **Symlink/dir rejection**: refuses to read or overwrite a symlink, directory, or special node at the config path (**hardening against symlink attacks**).
- **Size caps**: config ≤ 65 536 bytes; registry JSON docs ≤ 5 MB (`utils/registry.ts:5`).
- **Secrets**: none handled by config (config only stores a registry URL/path). Remote-registry URL is screened by `assertSafeRemoteUrl` (no embedded credentials).
- **Path traversal**: local registry source is `path.resolve(process.cwd(), source)` — users may pass arbitrary local files deliberately; config command treats them as an explicit user choice, but `joinRelativePathUnderRoot` (`core/src/urls.ts`) guards registry-item relative paths from escaping the index root (used at load time, not by config).
- **Env var handling**: `XDG_CONFIG_HOME` (config path) and `CHEETOS_REGISTRY` (registry load override in `utils/registry.ts`). Both injectable via `env` param for tests.

### Production dependencies used (test stubs/mocks needed)

All from `@cheetos/core`: `readJsonFileAsync` (`fs.ts:120`), `isMissingPathError` (`fs.ts:19`), `lstatAsync` (`fs.ts`), `readFileAsync`, `removeAsync`, `isAbsoluteHttpUrl` (`urls.ts:9`), `assertSafeRemoteUrl` (`urls.ts:110`). Command prompts: `textInput` (`cli/prompts.ts`) and `animatedIntro` (`cli/animated-intro.ts`) — the latter should be stubbed in command tests since it spins interactive output.

## Existing test scaffolding

- **Framework**: Vitest 3.2.4, config in root `vitest.config.ts` — `environment: "node"`, `globals: true` (Jest-style `describe/test/expect` with no imports).
- **File naming**: standard `*.test.ts`; Vitest default include `**/*.{test,spec}.?(c|m)[jt]s?(x)` (not overridden).
- **Location**: co-located in source dirs (`packages/*/src/**/*.test.ts`). CLI `tsconfig.json` excludes `**/*.test.ts` and `**/*.spec.ts`.
- **Test scripts**: root `pnpm -r --filter "./packages/*" run test`; per-package `test: "vitest run"` for both `cheetos` (cli) and `cheetos-core` (core); `@cheetos/registry` uses `vitest run --passWithNoTests`. Single shared root vitest.config.
- **Coverage**: `vitest run --coverage` with 80% thresholds (root `cov` script only runs core build).
- **Mutation**: Stryker (`stryker.config.mjs`), vitest-runner.
- **Existing tests**: **none** in the monorepo for cli/core/registry. The only `*.test.ts` files on disk live under `.pi/git/...` (a vendored third-party reference repo — **not** part of the workspace test suite). So `config` tests would be the first production tests; no helpers/mocks/tmp-fs utilities exist yet.

### Recommended setup for writing tests

- Drive all config primitives through the `env` param with a temp `XDG_CONFIG_HOME` pointing into `fs.mkdtemp` (os.tmpdir). No mocking needed for `cli/config.ts` — it is fully injectable.
- For `configGetCommand`/`configSetCommand`/`configUnsetCommand`, stub `temperature`/`animatedIntro` and `textInput` (via `vi.mock` on `../cli/animated-intro` / `../cli/prompts`) since they hit the terminal; assert return values and printed config.
- Probes: N/A (release/mutation tool). Stryker config exists.

### Behaviour contract

<Accordions>
	<Accordion title="configPath — location resolution">
		- `configPath#xdg-override`: a set `XDG_CONFIG_HOME` (trimmed) wins; result is `<base>/cheetos/config.json`.
		- `configPath#xdg-override`: a whitespace-only value falls back to the default base; a relative value resolves against the working directory.
		- `configPath#default-fallback`: without `XDG_CONFIG_HOME` the base is `~/.config` (`os.homedir()`).
	</Accordion>
	<Accordion title="readConfig — parsing, validation, and hardening">
		- `readConfig#missing-file`: absent file → `{}`; no directory is created.
		- `readConfig#round-trip`: a valid file parses; the `registry` value is trimmed.
		- `readConfig#root-shape`: `null`, number, string, or array root → wrapped `Malformed cheetos config at <path>: Config root must be a JSON object.`
		- `readConfig#malformed-json`: invalid JSON → wrapped error includes the path and `Fix or delete the file, then retry.`
		- `readConfig#unknown-keys`: any key other than `registry` is rejected.
		- `readConfig#registry-shape`: `registry` as number/object/empty/whitespace-only string is rejected.
		- `readConfig#size-cap`: > 65 536 bytes → `file is too large.` (thrown unwrapped, before parsing); exactly 65 536 bytes is accepted (boundary test).
		- `readConfig#symlink-rejection` / `#dir-rejection`: symlink or directory at the config path → `Cannot read cheetos config at <path>: …`.
	</Accordion>
	<Accordion title="writeConfig — atomic shape, permissions, and safety">
		- `writeConfig#dir-mode`: parent `cheetos/` directory is created recursively with mode `0o700`.
		- `writeConfig#file-mode`: config file is created with mode `0o600`.
		- `writeConfig#format`: tab-indented JSON plus a trailing newline; empty config serializes to `{}` + newline.
		- `writeConfig#normalization`: the persisted value is trimmed; only the canonical `registry` key survives.
		- `writeConfig#registry-shape`: non-string / empty / whitespace-only `registry` is rejected **and nothing is written**.
		- `writeConfig#round-trip`: write → read round-trips; a second write fully replaces the file (no merge).
		- `writeConfig#symlink-rejection`: refuses to write over a symlink — including a dangling one — and the symlink target's content is verified untouched (anti-tamper check).
		- `writeConfig#dir-rejection`: a directory at the config path → `Cannot write cheetos config at <path>: path is a directory.`
	</Accordion>
	<Accordion title="unsetRegistryConfig — clearing and idempotence">
		- `unsetRegistryConfig#clears-saved`: with a saved registry → returns `true` and deletes the whole file (not just the key).
		- `unsetRegistryConfig#missing-file`: no file → `false`, and neither file nor parent directory is created; a file without `registry` is left untouched.
		- `unsetRegistryConfig#idempotent`: a second unset returns `false`.
	</Accordion>
	<Accordion title="configSetCommand — source acquisition and policy">
		- `configSet#flag-path`: an explicit source is trimmed, validated, persisted; returns `configPath(env)`; the prompt is never shown.
		- `configSet#prompt-path`: a missing or whitespace-only source prompts via `textInput` with message `Registry URL or local path` and `{ placeholder, required: true }`; an empty prompt answer is rejected without writing.
		- `configSet#precedence`: setting replaces a previously saved registry.
		- `configSet#source-policy`: HTTPS-only remote URLs (`http://` rejected), no other schemes (`ftp://`), no embedded credentials, no `localhost` / `*.localhost`, no IP-literal hosts; local sources must be existing regular files (missing → lookup hint, directory / symlink rejected) resolved against the working directory.
		- Every rejection above is verified to leave the config file **unwritten**.
	</Accordion>
	<Accordion title="configGetCommand / configUnsetCommand — unset state">
		- `configGet#saved`: prints the saved registry and the config file path, with no `(not set)` line.
		- `configGet#not-set`: without a saved registry, prints `registry:    (not set)` plus a hint naming `cheetos configure set` — no bundled default URL exists anymore.
		- `configUnset#cleared`: returns `true`, deletes the file, and prints `(not set)` + hint (no more default-URL fallback).
		- `configUnset#nothing-saved`: returns `false` and also prints `(not set)` + hint.
	</Accordion>
	<Accordion title="CLI wiring — registerCommandsCli (public seam)">
		- `wiring#get|set|unset`: dispatches to the corresponding command under the `configure` command name; `set` without a source passes `undefined` (the command prompts itself).
		- `wiring#source-rejection`: `configure get <source>` / `configure unset <source>` → prints `configure <action> does not take a registry source.` and exits 1 without dispatching.
		- `wiring#action-validation`: unknown / wrong-case / empty actions → `Unknown configure action "<x>"` plus `Usage: cheetos configure <get|set|unset> [source]`, exit 1.
		- Note: cac's `parse()` never awaits the action promise, so error propagation is observed via `process.exit(1)` and the printed error, matching how `bin/cli.mjs` consumes it.
	</Accordion>
	<Accordion title="locateRegistry — source precedence (adjacent surface)">
		- `precedence#flag-beats-env|env-beats-saved|saved`: strict flag > `CHEETOS_REGISTRY` > saved config ordering; an explicit unsafe URL (HTTP / credentials) is rejected even as a flag; a relative flag source resolves against the cwd without existing.
		- `locateRegistry#no-source-throws`: no flag, env, or saved source → `NoRegistrySourceError` whose message names `cheetos configure set` (actionable remediation, replaces the old `Registry not found (registry.json)` build hint).
		- `locateRegistry#explicit-only`: a `registry.json` in the working directory is **not** discovered — no cwd/fallback/bundled candidate probing exists.
		- `locateRegistry#env-empty-shadows-saved`: an **empty** `CHEETOS_REGISTRY` shadows the saved config (kept `??` semantics) → `NoRegistrySourceError`.
	</Accordion>
</Accordions>

<Callout type="info">
	Isolation rule: every filesystem test drives a `fs.mkdtemp` root through the `env` / option seams — the real user config is never touched. Interactive terminal surfaces (`textInput`, `animatedIntro`) are the only modules mocked; the `locateRegistry` tests additionally spy on `process.cwd` (workers cannot `process.chdir`). Gaps left untested (declared, not hidden): FIFO/socket special nodes (no portable creation API in Node), the lstat→read vanish race in `readConfig`, and `OperationCanceledError` from prompt cancellation (now covered indirectly via the `add#prompt-cancel` wiring test in the inbuilt-registry-removal contract).
</Callout>

<Callout type="warn" title="Vader red-team adjudication">
	Technique classes exercised — all test-side, no production changes:

	- **Worker-incompatible cwd mutation**: `utils/registry.test.ts` used `process.chdir()`, which throws under Stryker's `pool: 'threads'` vitest runner (`process.chdir() is not supported in workers`) and aborted every mutation dry run. Replaced with a `vi.spyOn(process, "cwd")` seam; scoped mutation now runs.
	- **Ambient env leak**: no `CHEETOS_REGISTRY` reset, so a developer/CI env var could shadow the saved-config and fallback cases. Added a file-scope `beforeEach` delete.
	- **Assertion-light rejection tests**: the `ftp://`, `localhost`, `*.localhost`, IP-literal and directory source cases asserted the throw but not that the config stayed unwritten, despite the contract promising every rejection is verified unwritten. Also added the `Configuration` header and the `configUnset#nothing-saved` default-URL assertions.
	- **Unanchored scheme boundary**: the `scheme://` rejection was not pinned to the string start, so a local path containing a later `://` could be misclassified. Added a boundary test.
	- **Size-cap ordering**: added an oversized *invalid*-JSON case so a size check after parsing cannot pass. Added a `writeConfig` unknown-key test for the documented canonicalization quirk.

	Scoped mutation (`stryker run --mutate <4 config files>`, 397 mutants): **46.04%** overall (below `break: 70`) — `cli/config.ts` **91.5%**, `commands/config.ts` **73.4%**, `commands/index.ts` 32.6%, `utils/registry.ts` 7.1% (88 uncovered mutants are registry fetch/load code this suite never exercises). Remaining config survivors are the declared FIFO/socket and vanish-race gaps, the private `cliPackageVersion` validation paths the contract lists but tests cannot reach through the public interface, and equivalent defensive branches.
