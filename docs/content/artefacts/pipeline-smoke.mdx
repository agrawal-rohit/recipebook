## Plan

<Cards>
  <Card title="Dedicated trimRegistryUrl helper (recommended)" description="Risk: low">
    **Pros:** One call site change in client; easy to unit-test edges; reusable for compare/normalize later.

    **Cons:** New tiny module for a one-liner.
  </Card>
  <Card title="Inline .trim().replace(/\/$/, '') at call site" description="Risk: medium">
    **Pros:** No new file.

    **Cons:** Easy to miss a second call site; harder for oracle to cite a public surface.
  </Card>
  <Card title="Full URL canonicalize via WHATWG URL" description="Risk: high">
    **Pros:** Handles host case, default ports, more.

    **Cons:** Overkill for registry base strings; changes semantics beyond whitespace/slash.
  </Card>
</Cards>

Out of scope: query/hash rewriting, HTTPS upgrades, host allowlists.

## Docs

<Panel title="What it does">
  Registry base URLs often arrive with copy-paste whitespace or a trailing slash.
  `trimRegistryUrl` makes them comparable and safe to join with paths.
</Panel>

```ts
import { trimRegistryUrl } from './trim-url'

trimRegistryUrl('  https://registry.example/ ')
// → 'https://registry.example'
```

<Note>
  Call once at the config boundary before storing or comparing bases.
</Note>
